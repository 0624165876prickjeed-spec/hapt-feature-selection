# A题实验设计与评价协议 v1.0

日期：2026-10-28。配套技术定义见04，机器可读配置见06，数据许可与环境核验见07。当前没有真实数据模型性能结果；以下网格、指标与规则在最终评价前确定。

## 1. 数据流与防泄漏规则

| 边界 | 必须执行的规则 | 审计证据 |
|---|---|---|
| 划分单元 | 先按官方受试者ID将全部连续记录分到21人开发集/9人测试集，再建立窗口；开发集内部3折仍按人 | split_manifest，subject与exp集合交集均为空 |
| 原始记录 | acc/gyro配对为同一采集单元；不把同一exp的不同片段分到不同集合 | record_manifest和窗口来源索引 |
| 重叠窗口 | 长128、步64；重叠只在所属分区内部；不随机打散全部窗口后切分 | window_manifest，包括原始记录ID及采样区间 |
| 拟合步骤 | 每折参考功率、常数掩码、MI、D_j、相关矩阵、所选列、标准化和分类器全部只fit当前训练折 | 每个拟合对象保存fit_subject_ids与fold_id |
| 验证集 | 是开发集的一部分，仅用于候选配置比较；不得参与当前折fit。验证噪声用当前训练折参考功率生成 | CV配置与训练来源 |
| 最终模型 | 超参数选定后，从头在完整21人开发集fit；不简单复用某个CV模型 | final_fit_manifest |
| 测试集 | 冻结后只用于最终评价；不选K/λ、不重拟合标准化、不改噪声级别和边界规则 | 协议与冻结模型哈希、评价时间与日志 |
| 标签使用 | 只作监督训练、内部配置评价、稳定活动域过滤及最终算分；不把ID/标签/边界位置作为特征 | 特征名称仅来自固定66维信号特征 |
| 当前已做审计 | 测试原始数据仅检查结构、有限值和可生成窗口数；没有提取判别统计、调参、拟合或算准确率 | work中的可行性审计说明 |

确定性的单窗特征可按分区预先计算并缓存；任何训练相关统计必须按折独立计算。缓存键至少含ZIP哈希、分区/记录、窗口规则、特征版本、噪声配置及种子；带fit状态的缓存还必须包含训练受试者集合。标签相同或窗口数相似都不能替代来源审计。

## 2. 模型组与公平比较

| ID | 方法 | 选择评分 | 定位 |
|---|---|---|---|
| B0 | 全部有效特征＋线性SVM | 不筛选，λ=β=0 | 全维基础对照，维度不同，不能独自证明某个模块有效 |
| B1 | 互信息筛选＋线性SVM | I_j | 常规判别力基线；同时是去掉两项的消融 |
| B2 | 互信息＋冗余约束＋线性SVM | I_j−0.1R | 最接近的实验基线；相当于P去掉稳定性项 |
| A1 | 互信息＋稳定性＋线性SVM | I_j−λD_j | P去掉冗余项的消融 |
| P | 完整联合筛选＋线性SVM | I_j−λD_j−0.1R | 待检验方案 |

所有组：同一记录与窗口、同一66维候选集和常数掩码、同一分类器参数与线程数、同一内部折、相同验证和测试噪声实例、相同K（同预算图表中）、相同指标。B0/B1/B2不接触测试信息；A1/P使用的额外训练噪声只计算筛选惩罚，主实验没有把加噪训练窗拼进分类器训练。

B1/B2的K∈{20,40,60}。A1/P同样的K，λ∈{0.25,0.5,1}。β固定0.1，C固定1，不进行模型专属分类器调参。

为了区分模块作用与λ搜索带来的收益，额外保存**λ固定为0.5**的A1/P同K结果，与B1/B2比较；这些模型按协议冻结后才统一评价。λ=0直接对应B1/B2，不必重复训练名称不同但数学相同的模型。

可选后续对照：在开发集内按同规则对B2加入高斯训练数据增强，用于比较筛选与常见增强路线。默认不执行，以控制首版范围；不能在看到测试结果后只追加有利对照。若扩展，应作为明确的新版本，并保留当前冻结结果。

## 3. 噪声定义：参考SNR与实现SNR分开

用04定义的P[T,c]，指定γ dB。

`SNR_ref,c = 10log10(P[T,c]/E[ε_c²]) = γ`

主噪声：独立、零均值加性高斯噪声，`ε[r,t,c] ~ N(0,P[T,c]·10^(−γ/10))`。

外推压力测试：稀疏脉冲噪声，`ε=b·v`，`b~Bernoulli(p=0.01)`，`v~N(0,P[T,c]·10^(−γ/10)/p)`，二者独立。因此其期望噪声功率与同γ的高斯条件一致，但分布更尖峰。脉冲在各通道独立出现，不声称复现真实硬件故障。

| 条件 | SNR设置 | 用途 |
|---|---|---|
| 干净 | 不加噪，γ=+∞ | 基本识别能力与代价检查 |
| 训练稳定性估计 | 高斯20 dB，3次扰动 | 仅训练折D_j估计，不向分类器添加训练样本 |
| 内部验证 | 干净、高斯20/10 dB；2个验证噪声种子 | 调K/λ；最终测试不参与 |
| 最终主测试 | 高斯30/20/10/0/−5 dB；每级5个测试噪声种子 | 完整曲线，从轻微到强干扰，所有条件必须报告 |
| 最终外推压力测试 | 脉冲20/10/0 dB；每级同样5个测试种子 | 不曾用于D_j拟合或调参，检验对不同分布的有限外推 |

加噪位置：**已划分的整条原始记录→逐通道加噪→按冻结索引分窗→特征提取→训练标准化变换→固定分类器**。对所有组复用相同加噪记录/特征缓存。没有在特征向量上直接加噪，也没有先滤波再注入噪声。

γ是相对训练参考交流功率的SNR，不是按每条测试记录/每个静止窗口自适应调节的SNR。最终评价中另外记录各记录各通道的实现值：

`P_raw[r,c]=mean_t(x[r,t,c]−mean_t x[r,t,c])²`

`P_noise[r,c]=mean_t ε[r,t,c]²`

`SNR_realized[r,c]=10log10(P_raw[r,c]/P_noise[r,c])`。

这里实现值对整条原始记录计算，是事后诊断，不用于调噪、重新选条件或模型。P_raw=0且P_noise>0时为−∞，两者均0时记未定义；干净条件记+∞而非除零。高斯有限长度样本的噪声功率会有波动，不对每记录或每窗口重新归一化。加速度保留g，角速度保留rad/s；每通道独立按对应单位功率加噪。

## 4. 随机性与复现

| 项目 | 预设值 |
|---|---|
| 训练/MI种子 | 101、202、303；3次完整训练重复，全部保留，不挑最好seed |
| 训练稳定性扰动重复 | 每训练种子内b=0、1、2，统一汇总到D_j；不是三套不同增广训练集 |
| 内部验证噪声根种子 | 701、702；与训练扰动、最终测试种子隔离 |
| 最终测试噪声根种子 | 1101、2202、3303、4404、5505；跨方法、跨训练重复共用 |
| 配对受试者bootstrap | 99001，2000次，按人重采样 |
| CPU线程 | 数值库单线程；n_jobs=1；不同时启动多份完整实验 |

记录级噪声使用NumPy SeedSequence，固定熵向量：

`[root_seed, stage_id, fold_id, experiment_id, subject_id, noise_type_id, snr_db+100, replicate_id]`。

stage_id：训练稳定性11、内部验证21、最终测试31；noise_type_id：高斯1、脉冲2。fold_id为0/1/2，完整开发集/最终测试为99。训练扰动root_seed为对应训练种子，replicate_id=0/1/2；验证/测试root_seed来自其种子列表，replicate_id=0。测试熵向量**不包含方法名、K、λ或训练种子**，确保所有模型看到同一份测试噪声。snr_db+100使所有熵分量非负，禁止用Python hash生成随机种子。

## 5. 参数选择与冻结

每个训练种子独立进行相同3折开发集验证。对每个候选配置，各验证受试者在各条件计算六类Macro-F1：

`V = 0.5·F_clean + 0.25·mean_seed F_AWGN20 + 0.25·mean_seed F_AWGN10`。

每个F先在单个受试者的全部保留窗口计算，再对该折7人等权平均；最终对3折等权平均。这样验证各21人等权，而不是长记录受试者占更大权重。

选择V最大的候选。分差≤1e−4视为并列，依次优先：更高干净验证分、更小K、更小λ。对于固定K对照，只在该K内选择λ；另外从全部K中选择各方法部署配置。固定λ=0.5的诊断不重新调λ。β和C不调参。

正式评价前冻结：协议、数据/划分/窗口/特征版本、全部待比较配置、训练种子、噪声网格与种子、模型与拟合对象、指标脚本版本。冻结后运行的是一个统一评价批次；其中多个SNR/seed/模型不构成允许反复调参的“多次开放测试”。发现代码错误必须记录错误、作废受影响结果、升级版本并完整重跑相关条件，不能悄悄替换表格。

## 6. 任务匹配的指标与不确定性

类别数C_y=6。单个受试者内对类别k：`F1_k=2TP_k/(2TP_k+FP_k+FN_k)`；分母为0时置0（固定labels=1..6，zero_division=0）。`MacroF1_u=(1/6)Σ_k F1_(u,k)`。

主指标：`M=(1/U)Σ_u MacroF1_u`，最终U=9人；按训练种子和测试噪声种子分别算，再对3×5个组合等权平均。干净条件只有3个训练重复，不人为复制5遍充当更多样本。

| 指标 | 角色与解释 |
|---|---|
| 受试者平均Macro-F1 | 主指标，六类与每个人等权 |
| pooled Macro-F1、准确率 | 补充指标，在全部测试窗口上汇总；明确与主指标不同 |
| 每类召回、混淆矩阵 | 解释坐/站、上下楼等具体误差；汇总矩阵可报告重复的均值及行归一化形式 |
| 性能退化Δ(γ)=M_clean−M(γ) | 衡量噪声造成的下降；允许为负，不截断 |
| 全高斯网格平均R=(1/5)Σ_(γ=30,20,10,0,−5) M(γ) | 主鲁棒性摘要，五个预设条件等权，是人为压力测试摘要，不能当实际噪声发生概率 |
| 相同K的P−B2、P−A1、A1−B1 | 解释稳定性与冗余模块的贡献，优先报告效应大小和方向 |
| 所选维数、训练折间Jaccard | 约减与选择一致性；J(A,B)=count(A∩B)/count(A∪B)，并集为空时不适用；不同折K_eff不同时注明 |
| 特征提取/筛选/训练时间，端到端推理延迟与峰值RSS | 验证计算代价；先算完整66维再选列，不能宣称免去未选特征计算 |

不确定性分开报告：各训练/噪声seed的原始结果、跨seed波动、按测试受试者成对bootstrap的95%百分位区间。bootstrap先对每个人汇总3个训练重复、5个噪声重复的目标分数/差值，再按9个人整组有放回抽样2000次。固定模型与这9名受试者条件下的区间不等于人群普遍保证；窗口重叠、噪声重复和训练seed均不作为独立受试者。9人样本量有限，不以大量窗口制造过小p值。

效果目标仅用于解读：检查≤60维时干净主指标相对同K B1是否下降超过1个百分点，以及20 dB下是否较B1改善2个百分点；同时必须对B2和完整网格报告差异。未达标或区间跨0时如实说明，不能因未达标删除强噪声或改测试协议。

## 7. 实验矩阵与计算预算

| 实验 | 范围 | 用途 |
|---|---|---|
| E01 来源与泄漏审计 | 全部61记录，固定受试者分组、窗口来源和拟合来源检查 | 必须通过，违规计数=0 |
| E02 内部模型选择 | B0：1；B1/B2：各3；A1/P：各9个候选；3折×3训练种子 | 25×3×3=225次分类器fit上限（不含收敛补救） |
| E03 完整开发集重拟合 | 每训练种子，B0加4种筛选方法×3个K | 13×3=39次fit；选择部署K直接复用已训练模型 |
| E04 固定λ消融 | A1/P、λ=0.5、3个K、3训练种子 | 最多18次额外fit；和E03重复的配置复用 |
| E05 最终主评价 | 全部冻结配置；干净与高斯5级×5测试种子 | 按条件缓存特征，预测阶段不再次fit |
| E06 外推压力测试 | 同一模型；脉冲3级×5测试种子 | 不用脉冲条件调参，所有级别均保留 |
| E07 代价与误差分析 | 同设备单线程；同窗口批量；warmup1次、计时5次 | 报中位数与范围、实际批量大小；失败例按预设类/噪声条件抽取 |

训练次数上限约282次小型线性分类器fit，通常因复用更少。大部分计算是可缓存的特征和训练折MI，而非大模型训练；每折/训练seed只计算一次MI和每维稳定性，不为每个K/λ重复计算。

内存策略：连续记录逐条读取；特征按条件逐批写盘，禁止同时驻留40种全部加噪窗口。全部9718个窗口的float64六通道数组理论约56.94 MiB，66维特征约4.89 MiB；这只是数组主体，不等于进程RSS。预算目标峰值RSS<1.5 GiB，运行前检查可用内存至少2 GiB；低于此值先降低缓存/批量或顺序执行，不改变评价条件。当前机器16 GB，但核验时可用内存约2.49 GiB，因此不并行跑多份模型。

正式编码后先在开发集记录上做小规模计时，目标为确定真实运行时间和峰值内存。当前仅证明数据可解析、所需接口可运行，不把环境检查耗时当全套实验耗时；完整流程暂估几十分钟至数小时，须实测。

## 8. 编码阶段的验收门槛

| 门槛 | 必须验证 |
|---|---|
| G1 采集单元边界 | 人/记录集合不交叠；窗口不越界、不跨标签边界；不拼接记录 |
| G2 拟合隔离 | 改动验证/测试数值时，训练均值/MI/D/所选列不变；所有fit对象能列出训练受试者 |
| G3 噪声一致 | 同一原始采样的重叠窗噪声一致；跨方法同seed同条件噪声逐元素相同；功率生成不读取测试参考功率 |
| G4 数值边界 | 常数信号、IQR=0、全MI=0、短区间、非有限、K>d、评分并列的行为符合04 |
| G5 可复现与公平 | 同环境同seed重复一致；参数/折/分类器相同；无算法私有调参或静默剔除条件 |
| G6 冻结后评价 | 只有锁定清单里的模型与条件，评价过程不发生fit；预测可追溯至模型/数据/配置哈希 |

这些是后续编码需要实现的有意义验证，不表示当前已有相应课程实现或测试通过。当前阶段只完成了数据结构核验、环境/接口冒烟检查及方案文件。
